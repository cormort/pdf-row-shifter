# PDF 資料列分頁調整

瀏覽器裡直接調整 PDF 表格的分頁位置，不用重排原始文件。單一 HTML 檔，開了就能用。

**線上版**：https://cormort.github.io/pdf-row-shifter/

## 功能

- **保留原版面**：用 pdf.js 抽出文字與框線，依原始座標絕對定位，天地線／欄線／頁首都固定不動。
- **調整分頁**：`↓ 最後一列推到下頁` / `↑ 下頁第一列拉上來`，或直接拖曳任一列到新位置。
- **群組**：點一下選起點、Shift 點終點選一段，組成群組後一起搬，不會被分頁拆開（給跨行的計畫名稱用）。
- **行距自動微調**：非最後一頁的列平均分佈到表身底端，抽掉或塞入列都不會在頁尾留下突兀空白；超量時等比壓縮，不會越過地線。
- **對開表**：勾選後把單數頁（左半）＋雙數頁（右半）合成一個版面編輯，列印時再切回兩張 A4，頁碼左右各自重編。
- **就地編輯**：雙擊任一格改字，Enter 存檔、Esc 放棄。
- **對齊**：⌥（Option）點格選取，靠左／置中／靠右／水平均分／依欄線置中。
- **復原 / 重做**：⌘Z、⇧⌘Z（Windows 為 Ctrl+Z、Ctrl+Shift+Z）。介面上的按鍵標示會依平台自動切換。
- **忠實還原**：保留原檔的粗體、字型family（中文正黑／數字 Times）、框線粗細；文字以實測基線定位，並依原檔寬度校正，不會壓到欄線。
- **輸出**：瀏覽器「列印 / 存成 PDF」，紙張尺寸自動取自來源 PDF、無邊界。

## 平台

macOS 與 Windows 的 Chrome / Edge 都可用。Windows 上通常直接就有這類公文表原本用的
微軟正黑體與 Times New Roman，還原度會更好；若機器缺少對應字型，程式會量測實際字寬並
自動校正，版面（欄線、分頁、基線）仍然對齊，只是字形不同。

## 框線偵測：什麼條件下線條才會正常

框線是從 pdf.js 的 operator list 自己追 CTM 還原出來的。用 13 份實際公文表做過驗證
（把同一頁點陣化到 4 倍，掃出暗色貫穿帶當真值，再與抽取結果逐條比對位置／長度／厚度），
必須同時成立的條件如下：

| 條件 | 說明 | 實測 |
|---|---|---|
| 線是水平／垂直的 `lineTo` 或扁矩形 | 斜線、曲線一律丟掉 | 13 份 0 條斜線 |
| 線寬取得正確 | 沒下 `setLineWidth` 時要用 PDF 規格預設值 **1.0**；明寫 `w 0` 是 hairline，才當 0.5 | 見下方 |
| 線寬隨 `q`/`Q` 存回 | 線寬是圖形狀態的一部分，只存 CTM 會讓內層線寬外洩 | 已修正 |
| 長度 > 2pt 才留 | 濾掉標記點 | 0 條被誤丟 |
| 矩形短邊 ≤ 2pt 才算線 | 長寬都 > 2 視為填色色塊丟棄 | 丟掉 34 個色塊（44×17、143×16），全是填色 |
| 厚度相接／重疊且長度有交集才合併 | 兩道相接的 1pt 併成一條 2pt | 前提是線寬正確 |
| 橫貫線需覆蓋表寬 90% | 用來定天地線與表頭切點 | 13 份皆成立，未退回 fallback |

**曾經踩到的坑**：有些檔（例：`03-參考-OF-01-主要營運`）整份沒有任何 `setLineWidth`，
若把預設線寬當成 0.5，合併時厚度區間碰不到，本來一條 2pt 的天地線就會裂成兩條 1pt，
`spanning()` 也會吐出重複的 y（89 與 90、800 與 801），連帶讓表身下界差 1pt。
預設改為 1.0 之後，13 份檔案的線條位置與厚度全部與點陣化真值一致。

## 限制

- 需要連網（pdf.js 從 CDN 載入）。
- 只處理文字型 PDF，掃描檔沒有文字圖層。
- 編輯以 PDF 原本的文字片段為單位；美術字距的標題在原檔是一字一片段，需逐字改。
- 框線偵測假設表格有橫貫全寬的天地線，特殊版型可能要調整。
